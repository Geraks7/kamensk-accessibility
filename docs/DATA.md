## Что сложно и почему это не блокер

| Данные | Проблема | Решение |
|---|---|---|
| Вместимость школ и детсадов | в перечнях нет; только карточки `bus.gov.ru` по одному учреждению | **не нужно для MVP**: сценарий строится на покрытии, а не на мощности. Собрать по 10–15 объектам, если останется время |
| Функциональные зоны (ФГИС ТП) | официальной выгрузки нет; технически возможен GeoJSON через WFS (`mnp.economy.gov.ru/geoserver`, неофициально) | отложить на v2 |
| Аварийный жилищный фонд | ГИС ЖКХ / ФРТ — веб-реестр, машиночитаемой выгрузки по городу нет | ручная выборка 20–30 домов как иллюстрация, не как слой |
| Санитарно-защитные зоны | открытого реестра нет, только генплан / ЕГРН | оцифровать 2–3 крупнейших СЗЗ с карты генплана |
| Границы кварталов | в открытых данных нет | гексагональная сетка H3 — и выглядит профессиональнее |

## Ограничения, которые надо указать в README и в методике

1. Население по кварталам не публикуется → прокси по числу и площади жилых зданий OSM.
2. POI в OSM неполные → обязательная сверка с официальными перечнями.
3. Пешеходная сеть OSM неровная: тротуары и переходы покрыты неравномерно →
   проверить на 2–3 известных участках и написать.
4. В ГАР/ФИАС (`data.nalog.ru/opendata/7707329152-fias`) нет координат — только
   адресная иерархия и GUID, нужен геокодинг (Nominatim с ограничением частоты).
5. Вместимость объектов отсутствует → сценарий оценивает доступность, а не загрузку мест.

## Лицензии

- OSM — ODbL 1.0, обязательна атрибуция «© OpenStreetMap contributors».
- GHSL, Sentinel-2, Landsat — свободные, с указанием источника.
- Официальные перечни и PDF — государственные документы, ссылка обязательна.

## Порядок работы с данными

1. OSM PBF → граф и базовые слои.
2. Официальные перечни → сверка POI, ручное дополнение.
3. Таблица `docs/sources.csv`: источник — что взяли — что не сошлось — дата.
   Это не бюрократия: на защите и в README она показывает аккуратность.
