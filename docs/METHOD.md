# Методика расчёта

Документ описывает модель, показатели и допущения. Рассчитан на читателя, который хочет
воспроизвести результат или оспорить допущения.

## 1. Данные

| Слой | Источник | Формат | Ограничение |
|---|---|---|---|
| Пешеходный граф | OpenStreetMap (Geofabrik, УрФО → вырезка по границе ГО) | GraphML | тротуары закартированы неравномерно |
| Граница городского округа | OSM, relation 1298867 | GeoPackage | упрощённая граница |
| Объекты инфраструктуры | OSM (`amenity=school/kindergarten/clinic/hospital/doctors`) | GeoPackage | неполнота, проверяется по `obr-ku.ru`, `miacso.ru` |
| Жилая застройка | OSM (`building=residential/apartments/house/...`), центроиды | GeoPackage | только закартированные здания |
| Нормативы | СП 42.13330 | константы | редакция требует проверки |

Файлы-кэши: `data/processed/buildings_residential.gpkg`, `data/cache/`.

## 2. Модель доступности

1. Граф проецируется в UTM 41N (EPSG:32641), длины рёбер — в метрах.
2. Каждый объект и каждое жилое здание привязываются к ближайшему узлу графа
   (`sjoin_nearest` по спроецированным координатам).
3. Для каждого типа объектов считается кратчайшее расстояние по сети от каждого узла
   спроса до ближайшего объекта: одна задача «много источников» —
   `nx.multi_source_dijkstra_path_length` с весом `length`.
4. Расстояние переводится во время: `t = d / v`, где `v = 4,5 км/ч` (базовая),
   проверяется также 4 и 5 км/ч.

Порог доступности — 15 минут (1125 м при 4,5 км/ч). Дополнительно считаются 10 и 20 минут.

## 3. Показатели

**Покрытие** — доля жилых зданий, от которых время до ближайшего объекта не превышает порог:

```
coverage = Σ w_i · [t_i ≤ T] / Σ w_i
```

где `w_i` — число зданий на узле спроса `i`.

**Дублирование** — для каждой точки спроса считается число объектов `n_i`, достижимых за
порог. Отчётные величины: доля жилья с `n_i ≥ 2` (избыточность) и с `n_i = 0` (дефицит).

**Нормативный baseline** — сравнение одного и того же расстояния, измеренного двумя
способами: по прямой (как в нормативе) и по улично-дорожной сети. Разрыв показывает,
насколько уличная сеть и барьеры «съедают» нормативный радиус.

**Критичность объекта** — маргинальная потеря покрытия при удалении только этого объекта:

```
loss_j = Σ_{i ∈ C_j, n_i = 1} w_i
```

где `C_j` — множество точек спроса, достижимых от объекта `j`, `n_i` — число объектов,
покрывающих точку `i`. Считаются только точки, которые покрыты исключительно этим объектом.

## 4. Сценарии

Жадный алгоритм (`04_scenario.py`):

1. Считается базовое покрытие `B`.
2. Для каждого активного объекта оценивается `loss_j`.
3. Выбирается объект с минимальной потерей; если суммарная потеря не превышает бюджет
   сценария — объект удаляется, счётчики покрытия пересчитываются.
4. Шаги повторяются.

Бюджеты: 0 % (умеренный), 1 % (средний), 3 % (радикальный) от общего числа зданий.
Ограничение: не более 50 % объектов типа — модель не учитывает вместимость, поэтому
формально «без потерь» можно убрать почти всю сеть.

Дополнительно для каждого сценария считается среднее время до ближайшего объекта — оно
растёт даже там, где двоичное покрытие не меняется.

## 5. Допущения

- Пешеходная доступность считается по кратчайшему пути; реальные маршруты могут быть
  длиннее (переходы, ограждения, рельеф).
- Скорость постоянна; не учитываются возраст, сезон, состояние тротуаров.
- Все здания равнозначны: нет весов по числу жителей, площади и возрасту.
- Вместимость объектов не учитывается — только пространственная близость.
- Общественный транспорт не включён: поездка на автобусе не засчитывается как доступность.

## 6. Оценка чувствительности

Пересчёт выполняется при:

- пороге: 10 / 15 / 20 минут;
- скорости: 4 / 4,5 / 5 км/ч;
- составе объектов (после сверки с официальными перечнями);
- границах территории (город или округ с посёлками).

## 7. Воспроизводимость

```
src/01_city_map.py      граница + граф + карта
src/02_poi.py           объекты из OSM
src/03_accessibility.py покрытие, дублирование, baseline
src/04_scenario.py      сценарии и критичность
src/05_maps.py          статические карты
src/06_webmap.py        интерактивная карта
```

Запуск: `pip install -r requirements.txt`, затем скрипты по порядку. Все пути считаются от
корня репозитория, запуск возможен из любой папки. Кэш запросов — в `data/cache/`.

## 8. Что не учтено и что это меняет

- **Вместимость.** Школа на 200 и на 1200 мест в модели равны. Поэтому оценка избыточности
  сети — верхняя граница: половину объектов можно убрать «без потери покрытия», но не
  «без потери мест».
- **Возрастная структура.** Детсады нужны семьям с детьми, поликлиники — пожилым.
  Без данных о возрасте по кварталам спрос считается однородным.
- **Барьеры.** Промышленные зоны и санитарно-защитные зоны влияют через геометрию сети,
  но отдельным слоем не введены.
- **Динамика.** Расчёт — срез на момент выгрузки OSM; тренд населения не моделируется.
